# OpenShell compatibility doctor

The `doctor` command inspects an already provisioned OpenShell sandbox using only
`sandbox get` and `policy get`. It checks the CLI binary digest, lease expiry,
sandbox UID and phase, policy sandbox, loaded status, requested active revision
and effective policy digest. It does not provision, execute workload code, mutate
policy, delete resources or contact receipt/monitor services.

Supply private, trusted operator configuration independently of CLI output:

```sh
agent-boundary-gate doctor \
  --executable ./operator/openshell \
  --executable-digest "$OPEN_SHELL_CLI_DIGEST" \
  --gateway "$GATEWAY_NAME" --sandbox "$LEASED_SANDBOX_NAME" \
  --policy-revision "$REQUESTED_POLICY_REVISION" \
  --lease ./operator/lease.json --probe-runtime perl --timeout 10
```

The paths and environment variables are placeholders for operator-owned inputs;
they are not generated by this command. Keep configuration, binaries and lease
files outside the public checkout. `--lease` reads the existing `LeaseBinding`
JSON contract, including its boundary component UID, effective policy digest and
expiry. The file's provenance must be trusted: parsing a lease is not authenticating
its issuer. Policy revision is a trusted requested revision, not a constant inferred
from an earlier run. See the [live-rig handoff](live-rig-handoff.md).

The executable must be a regular file at its actual path, not a symlink, and match
the supplied `sha256:` digest. Inputs are bounded: lease JSON at 64 KiB, CLI binary
at 64 MiB and each CLI response at 64 KiB. The timeout must be finite, positive
and at most sixty seconds; both queries share it. Existing process-group cleanup
can take up to five additional seconds. Keep the executable and its parent
directories controlled by the operator; digest checks before each invocation do
not prevent a malicious concurrent executable replacement between checking and
launching. The doctor trusts the pinned CLI's implementation of read commands.

The report contains only fixed check names, statuses and error codes. It omits
gateway/sandbox names, UIDs, digests, lease identifiers, paths and raw CLI output.
Matching observations produce `status: observations-match` and exit 0. Mismatches
or unavailable observations produce `status: incompatible` and exit 2. Invalid
input also exits 2 with the CLI's sanitized input error. These codes describe
compatibility observations only; they are not gate decisions.

Every report explicitly retains:

```json
{
  "probe-runtime": "unverified",
  "authenticated-readiness": "unverified",
  "ready_for_attempt": false,
  "qualification": "m0-prototype",
  "release_eligible": false
}
```

`--probe-runtime` selects the prerequisite list to report. Python requires
`python3` and `urllib.request`; Perl requires `perl`, `IO::Socket::IP` and `Socket`.
The doctor cannot establish their availability without executing inside the
workload. The [Perl rationale and runtime requirements](live-rig-handoff.md) and
[Rust exploration](rust-probe-exploration.md) explain the current choices. There
is no fallback or Rust runtime selector.

A matching report does not prove containment, workload image identity, supervisor
generation, policy enforcement, healthy independent monitoring or whole-cell
cleanup. `OpenShellBackend.readiness` still requires a fresh authenticated broker
receipt, and an actual attempt still requires independent monitoring and outcome
observations. Latency experiments and probe execution belong in a separately
designated disposable lease with authenticated cleanup; this command does not
perform them.

Python callers can use `agent_boundary_gate.doctor.openshell_doctor` with the same
keyword inputs and a trusted `LeaseBinding`. It returns the same sanitized dict
without printing. See the [library guide](library-usage.md) for orchestration APIs.
